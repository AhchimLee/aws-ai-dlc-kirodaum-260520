# AWS Summit Seoul 2026 — AI-DLC Challenge 제출 가이드

## FAQ · 제출 가이드

제출 방식, 포맷, 평가 기준에 대한 자주 묻는 질문입니다.

---

## 제출 한눈에 보기

① 로그인 → ② Git URL 또는 zip 중 하나 선택 → ③ 제목·설명·팀원 입력 → ④ 데모 미디어(선택) → ⑤ 제출 버튼.

- zip ≤ 200MB
- 이미지 ≤ 10MB (자동 축소)
- public GitHub 만
- 재제출 = v1, v2 자동 누적
- manifest.json PUT 시 자동 평가

---

## 제출 방식

### 제출 방식이 어떻게 되나요?

두 가지를 지원합니다.

- 공개 GitHub repo URL — 기본 branch의 tarball을 자동으로 가져와 평가합니다. 비공개 repo는 지원하지 않습니다.
- 소스 zip 업로드 — 브라우저에서 presigned URL로 S3에 직접 업로드. 최대 200MB.

---

## 제출 포맷

### 소스 zip은 어떤 구조여야 하나요?

루트(/)에 다음을 권장합니다.

- README.md — 프로젝트 개요·실행 방법·사용한 AI 도구 (필수 권장)
- src/ 또는 실제 소스 트리
- aidlc-docs/ — Spec, 설계 노트, AI 대화 로그 등 AI-DLC 산출물
- screenshots/ 또는 result/ — 동작 캡처

평가 에이전트는 README와 위 산출물을 우선 분석합니다. node_modules, .git, __pycache__ 등은 자동으로 제외됩니다.

---

## 제출 포맷

### 파일 크기 / 개수 제한은?

- 데모 미디어(스크린샷): 단일 파일 ≤ 10MB · 합계 ≤ 200MB · PNG, JPG, JPEG, WebP만
- 10MB 초과 이미지는 브라우저에서 비율을 유지하며 자동 축소됩니다 (한 번에 가로/세로 80%씩, 10MB 이하가 될 때까지).
- 소스 zip: ≤ 200MB
- 압축 해제 후 총 크기 ≤ 1GB, 멤버 수 ≤ 10,000 (zipbomb 방지)
- 평가 단계에서 단일 파일 ≤ 10MB, 총 ≤ 100MB, 파일 수 ≤ 1,000개로 다시 필터링

---

## 재제출

### 재제출하면 이전 제출이 사라지나요?

아니요. 같은 팀이 여러 번 제출하면 v1, v2, v3 … 으로 자동 누적됩니다. S3 경로는 submissions/{team-id}/v{N}/source/ 형태로 저장되며, 갤러리에는 각 팀의 최신 제출 1건만 표시됩니다. 평가는 새 버전마다 다시 실행됩니다.

---

## 평가

### 제출 직후 평가는 어떻게 시작되나요?

파일 업로드가 끝나고 manifest.json이 마지막에 PUT되는 순간, EventBridge 규칙이 단 한 번 발화하여 AgentCore Runtime을 호출합니다. 사용자에게는 "제출됨" 응답이 즉시 반환되고, 평가는 백그라운드에서 진행됩니다. 결과는 별도 리더보드에서 확인하세요.

---

## 평가

### 평가는 어떤 기준으로 채점되나요?

4개 Pillar로 구성된 100점 만점.

- 완성도 20점 — 기능 동작, 안정성, 운영 가능성, 보안
- AI-DLC 활용도 30점 — 워크플로우 문서, AI 대화, Spec 품질
- 기술 활용도 20점 — AI / AWS 서비스 활용, 통합, 확장성
- 창의성 & 임팩트 30점 — 고객 문제, 독창성, 비즈니스 영향

Agent 점수와 사람 심사위원 점수가 독립적으로 산출됩니다.

---

## 제출 방식

### GitHub URL의 특정 branch / commit으로 평가받을 수 있나요?

현재는 기본 branch(보통 main)의 최신 커밋만 지원합니다. 특정 commit 평가가 필요하면 zip 업로드를 사용하세요.

---

## 보안

### 제출한 소스코드는 누구에게 공개되나요?

갤러리에는 제목·팀명·설명·미디어만 표시됩니다. 소스 zip / git URL의 실제 코드는 본인 팀과 운영자만 다운로드할 수 있습니다. 평가 결과(점수)는 리더보드 정책에 따라 공개됩니다.

---

## 문제 해결

### 제출이 실패합니다. 무엇을 확인해야 하나요?

- zip 파일이 진짜 zip인지 (확장자만 바꾼 tar.gz는 거부됨)
- 심볼릭 링크 / 절대 경로(/etc/...) / ../ 멤버는 보안상 거부됨
- GitHub URL이 public이고 기본 branch가 존재하는지
- 업로드 중 페이지를 닫지 않았는지 (브라우저 탭 유지 필요)
- 여전히 안 되면 운영진에게 팀명·시각·에러 메시지 전달
