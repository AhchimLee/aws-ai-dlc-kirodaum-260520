# AI-DLC 이해하기

**1. AI-DLC는 무엇인가요?**

**AI-Driven Development Life Cycle (AI-DLC)** 는 복잡한 시스템을 대규모로 구축하기 위해 도구, 역할, 프로세스를 통합하도록 특별히 설계된 **AI 네이티브 개발 방법론**입니다.

기존 개발 방식에 AI를 단순히 추가하는 것이 아니라, **AI와 함께 일하는 방식을 처음부터 새롭게 설계**한 개발 프레임워크입니다.

**1.1. 왜 AI-DLC가 필요한가요?**

기존 AI 코딩 도구들은 코딩(전체 개발의 20%)만 가속화하여 전체 생산성은 10-15%만 향상됩니다.

**AI-DLC는 다릅니다:**

✅ 설계, 분석, 소통, 테스트까지 **100% 전체 개발 프로세스를 가속**

✅ **5-10배 생산성 향상**과 **엔터프라이즈 프로덕션 품질**을 동시에 달성

✅ AI가 계획하고 실행하면, 사람은 검증하고 의사결정에 집중

**1.2. 핵심 특징**

**AI와 사람의 협업**: AI가 프로세스를 주도하고, 사람이 전략적 결정을 내립니다.

**체계화된 검증**: 각 단계마다 리뷰/검증을 통해 프로덕션 품질을 보장합니다.

**구조화된 산출물**: 12개 이상의 설계 문서와 함께 코드, 테스트, 인프라가 생성됩니다.

**2. AI 개발 도구의 진화**

AI가 소프트웨어 개발을 어떻게 변화시켜 왔는지 살펴보겠습니다:

**2023년: 자동완성**

- 다음 몇 줄을 예측하여 코드를 더 빠르게 작성
- 개발자가 코드를 더 빠르게 작성할 수 있도록 지원

**2024년: 어시스턴트**

- 더 큰 규모의 코드 스니펫 생성 및 질문 답변
- 대화형 코드 생성과 설명

**2025년: 에이전트**

- 도구를 선택하고 사용할 수 있는 자율성을 가지고 복잡한 작업 수행
- 인간 참여형 엔드투엔드 개발 작업 완료

**2026년: 멀티 에이전트**

- 여러 에이전트가 특정 역할과 전문성을 가지고 협업하여 개발 수행
- 자율 동작하는 전문화된 에이전트 팀

AI가 이렇게 빠르게 진화하고 있지만, 실제 개발 현장에서는 기대만큼의 생산성 향상을 체감하지 못하고 있습니다. 왜 그럴까요?

---

**3. 현재의 한계점**

**3.1. 한계점 (1): AI 소프트웨어 생산성 역설**

많은 조직이 AI 개발 도구를 도입했지만, 기대만큼의 생산성 향상을 체감하지 못하고 있습니다:

- **10-15% 생산성 향상**: AI를 소프트웨어 개발에 활용해도 속도 향상은 고작 10-15%에 불과
- **오히려 느려지는 경우도**: 일부 연구에서는 AI 도구 사용 시 오히려 19% 더 오래 걸린다는 결과도 발표 ([METR.org](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/) )

**왜 이런 일이 발생할까요?**

![소프트웨어 개발의 실제](https://static.us-east-1.prod.workshops.aws/23768ace-c53e-436b-af8e-bdcda7ccf7be/static/images/aidlc/01-01.png?Key-Pair-Id=K36Q2WVO3JP7QD&Policy=eyJTdGF0ZW1lbnQiOlt7IlJlc291cmNlIjoiaHR0cHM6Ly9zdGF0aWMudXMtZWFzdC0xLnByb2Qud29ya3Nob3BzLmF3cy8yMzc2OGFjZS1jNTNlLTQzNmItYWY4ZS1iZGNkYTdjY2Y3YmUvKiIsIkNvbmRpdGlvbiI6eyJEYXRlTGVzc1RoYW4iOnsiQVdTOkVwb2NoVGltZSI6MTc3OTgwOTc3N319fV19&Signature=CYoOgjjtft4lrSa-zNToSaSd-VfT8Dqmx3KhWpF-KIhO4ztRS9y00knXSFozZhWjszd3HevYfPpGZKR2J4HFCVM%7EfdzvtkYeX2rGGtZ-DpGJsQfSuImf6UtIv1pHLjDon2syxLQzMP-Hs6mZaGJ7811EdLNw%7EAeSoWjlcsN7daXtOdIf2v1SiOi9RnTQLOZZUzHHSHSycGIM-DKZ9DlLAmOMyGYrAnwWn7FqSccyK%7EVZSpf%7EOjP8zGPUlHmTPiphntsGAc0GQxH88feVN8HGfguOebwXTMJAGae84X6UB55%7EH0Ls%7Erb-gS4jrm0ocMOO0D%7Evn5Tsqm0EAieWD5gvYw__)

**기존 AI 코딩 도구의 문제**: 전체 개발 프로세스 중 20%인 코딩영역을 50% 빠르게 해줘도, 전체 생산성은 10%만 향상됩니다.

**AI-DLC의 접근**: 코딩뿐만 아니라 설계, 분석, 소통, 테스트까지 **100% 전체 개발 프로세스를 가속**합니다.

---

**3.2. 한계점 (2): AI 코딩의 발전 단계와 각 단계의 문제점**

그렇다면 AI 코딩 도구들을 사용하는 방법은 어떻게 발전해왔을까요? 각 단계를 살펴보면서 왜 여전히 한계가 있는지 이해해봅시다.

[**발전 1단계: 바이브 코딩**](https://catalog.us-east-1.prod.workshops.aws/event/dashboard/ko-KR/workshop/01-introduction#1:)

`"로그인 기능 만들어줘"`

- AI에게 직접 요청하고 코드를 받음
- **문제점**: 끝없는 수정 루프에 갇힙니다
    - 1차 시도: 우리 기술 스택과 맞지 않거나..
    - 2차 시도: 기존 코드와 충돌하거나..
    - 3차 시도: 보안 요구사항이 누락됩니다
    - **"결국 직접 다 고치게 됩니다..."**

[**발전 2단계: 스펙 기반/플랜 기반**](https://catalog.us-east-1.prod.workshops.aws/event/dashboard/ko-KR/workshop/01-introduction#2:)

`기획서/스펙 작성 → AI가 스펙 기반으로 개발`

- **좋아진 점**:
    - 기본 구조가 명확해집니다
    - 반복 수정이 줄어듭니다
    - 일관성이 향상됩니다
- **여전히 남는 문제**:
    - 스펙에 없는 건 AI가 추측하여 결정합니다
    - 비기능 요구사항이 누락됩니다 (보안, 성능, 확장성)
    - 도메인 모델, 에러 처리, 로깅 등 디테일이 누락됩니다
    - 작성한 스펙이 "내 의도가 맞는지" 검증이 없습니다
    - **MVP/프로토타입 수준의 품질**

[**발전 3단계: AI-DLC**](https://catalog.us-east-1.prod.workshops.aws/event/dashboard/ko-KR/workshop/01-introduction#3:-ai-dlc)

`요구사항 → 구조화된 컨텍스트 문서 → 프로덕션 품질의 코드`

AI-DLC는 체계화된 프롬프트 체인을 따라 단계별로 실행하고 검증합니다:

1. **제품 요구사항 문서 (Product Requirements Document, PRD) 리뷰/검증** → 요구사항 명확화
2. **사용자 스토리 리뷰/검증** → 사용자 관점 확인
3. **도메인/API 설계 리뷰/검증** → 아키텍처 검증
4. **인프라 리뷰/검증** → 배포 환경 확인
5. **코드 리뷰/검증** → 최종 품질 확인

**결과**:

✅ **5-10배 생산성 향상**

✅ **엔터프라이즈 프로덕션 수준의 품질**

✅ **예측 가능한 결과물**

✅ **구조화된 컨텍스트 문서**

이제 AI-DLC가 이러한 한계를 어떻게 극복하는지 자세히 살펴보겠습니다.

**4. AI-DLC의 차별점**

**4.1. 대화 주도권의 전환**

**기존 방식: 인간이 명령, AI가 실행**

`여러분: "이 기능 만들어줘"
AI: "네, 만들었습니다"
여러분: "아니 이게 아닌데..."`

인간이 명령하고 AI가 따릅니다. 하지만 AI는 맥락을 모르고, 여러분은 모든 걸 설명해야 합니다.

**AI-DLC 방식: AI가 질문, 인간이 결정**

`여러분: "이런 시스템 만들고 싶어"
AI: "사용자가 누구인가요? 핵심 기능은 뭔가요?"
여러분: [답변]
AI: "그럼 이렇게 만들면 어떨까요?"
여러분: "좋아, 진행해"`

**AI가 대화를 주도**합니다. AI가 먼저 질문하고 제안하며, 여러분은 전략적 결정을 내립니다.

---

**4.2. AI와 사람의 역할 재정의**

[**AI의 역할: 실행과 문서화**](https://catalog.us-east-1.prod.workshops.aws/event/dashboard/ko-KR/workshop/01-introduction#ai-:)

- 요구사항을 분석하고 명확히 합니다
- 복잡도에 맞는 최적의 접근법을 계획합니다
- 간단한 변경은 빠르게, 복잡한 프로젝트는 꼼꼼하게 처리합니다
- 모든 결정과 근거를 문서화합니다
- 각 단계마다 명확한 체크포인트를 제공합니다

[**사람의 역할: 전략과 검증**](https://catalog.us-east-1.prod.workshops.aws/event/dashboard/ko-KR/workshop/01-introduction#:)

- 비즈니스 목표와 제약사항을 제공합니다
- AI의 제안을 검토하고 승인합니다
- 중요한 아키텍처 결정을 내립니다
- 품질과 비즈니스 목표의 일치를 보장합니다

**결과**: 개발자의 역할이 단순 구현에서 전략적 의사결정으로 확장됩니다.

---

**4.3. 속도와 품질의 동시 달성**

[**속도: 몇 주 → 몇 시간**](https://catalog.us-east-1.prod.workshops.aws/event/dashboard/ko-KR/workshop/01-introduction#:)

기존 방법론은 몇 주, 몇 달 단위의 긴 반복 주기로 설계되었습니다.

AI-DLC는 몇 시간, 며칠 단위의 신속한 주기를 수용합니다. 실시간 검증과 피드백이 가능해져 시장 출시 시간이 극적으로 개선됩니다.

- **기존 스프린트**: 2주 단위
- **AI-DLC 단위**: 몇 시간~며칠 단위

[**품질: 지속적인 검증**](https://catalog.us-east-1.prod.workshops.aws/event/dashboard/ko-KR/workshop/01-introduction#:)

빠르다고 품질이 떨어지는 게 아닙니다. 오히려 더 좋아집니다.

AI가 각 단계마다 확인하고 물어봅니다. 잘못된 방향으로 가기 전에 바로잡을 수 있습니다.

**파일 기반 협업**으로 모든 결정이 문서로 남아 추적 가능합니다. 품질이나 감독을 희생하지 않으면서도 빠른 전달이 가능합니다.

**5. AI-DLC의 핵심 원칙**

**5.1 설계 원칙**

**처음부터 AI를 고려한 설계**

- 기존 방식에 AI를 끼워넣는 게 아니라, AI와 함께 일하는 방식을 기본 원칙부터 새로 만들었습니다

**검증된 설계 기법 통합**

- Domain-Driven Design 같은 검증된 방법론이 AI-DLC의 핵심에 통합되어 있습니다

**5.2. 실행 원칙**

**AI 역량과 인간 감독의 균형**

- AI가 잘하는 것(계획, 코드 생성, 테스트)과 사람이 해야 하는 것(전략, 결정, 검증)을 명확히 구분합니다

**책임의 확장**

- 개발자가 단순 코딩을 넘어 아키텍처, 설계, 운영까지 더 넓은 영역을 다룰 수 있게 권한을 부여합니다

**6. AI-DLC의 3단계 프로세스**

**1단계: 프로젝트 정의 (Inception)**

**"무엇을 만들지 정하기"**

AI가 체계적으로 질문하며 요구사항을 수집합니다. 여러분이 답하면 AI가 작업을 개발 유닛으로 쪼개고 실행 계획을 수립합니다.

**2단계: 구축 (Construction)**

**"실제로 만들기"**

AI가 설계하고 코드를 생성합니다. 비즈니스 로직 설계부터 기술 스택 선택, 코드 및 테스트 생성까지 진행합니다.

**3단계: 운영 (Operations)**

**"배포하고 실행하기"**

AI가 배포를 준비하고 모니터링 설정을 합니다. 여러분이 최종 확인하고 배포합니다.
