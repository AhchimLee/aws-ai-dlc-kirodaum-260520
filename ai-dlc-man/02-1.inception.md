# 1단계: 프로젝트 정의 (Inception)

비즈니스 목적을 실행 가능한 개발 유닛으로 변환하는 단계입니다. "몹 엘라보레이션(Mob Elaboration, 집단 상세화)" 방식으로 제품 책임자, 개발자, AI가 협업하여 요구사항을 명확히 합니다.

---

**프로젝트 정의 단계 스테이지 요약**

| 스테이지 | 실행 조건 | 주요 산출물 |
| --- | --- | --- |
| **Workspace Detection** | 항상 | `aidlc-state.md` |
| **Requirements Analysis** | 항상 | `requirements.md` |
| **Workflow Planning** | 항상 | `execution-plan.md` |
| **Reverse Engineering** | 기존 프로젝트만 | `architecture.md`, `component-inventory.md` |
| **User Stories** | 사용자 영향 기능 | `personas.md`, `stories.md` |
| **Application Design** | 새 컴포넌트 필요시 | `components.md`, `services.md` |
| **Units Generation** | 복잡한 프로젝트 | `unit-of-work.md` |

---

**프로젝트 정의 단계의 스테이지들**

**항상 실행되는 스테이지**

**Workspace Detection (작업 공간 분석)** 프로젝트 타입(신규/기존)과 현재 상태를 분석합니다.

**Requirements Analysis (요구사항 분석)** 요구사항을 수집하고 검증합니다. 복잡도에 따라 상세 수준이 조정됩니다.

**Workflow Planning (워크플로 계획)** 어떤 스테이지를 실행할지 실행 계획을 수립합니다.

**조건부 실행 스테이지**

**Reverse Engineering (역공학)** 기존 프로젝트의 코드베이스를 분석합니다. 신규 프로젝트에서는 건너뜁니다.

**User Stories (사용자 스토리)** 사용자 중심의 스토리와 페르소나를 생성합니다. 사용자 영향이 있는 기능에서 실행됩니다.

**Application Design (애플리케이션 설계)** 고수준 컴포넌트와 서비스 레이어를 설계합니다. 새 컴포넌트가 필요할 때 실행됩니다.

**Units Generation (유닛 생성)** 시스템을 관리 가능한 개발 유닛으로 분해합니다. 복잡한 프로젝트에서 실행됩니다.

**진행 과정**

**1. Workspace Detection: 작업 공간 분석**

AI가 프로젝트를 분석합니다.

`분석 항목:
├─ 프로젝트 타입: 신규(Greenfield) vs 기존(Brownfield)
├─ 기존 파일 구조
├─ 사용 중인 기술 스택
└─ Git 상태`

**산출물**: `aidlc-docs/aidlc-state.md` (프로젝트 상태 추적)

**2. Reverse Engineering: 기존 코드 분석 (조건부)**

기존 프로젝트인 경우, 코드베이스를 분석합니다.

`분석 내용:
├─ 아키텍처 구조
├─ 컴포넌트 목록
├─ 기술 스택
└─ 의존성`

**산출물**:

- `inception/reverse-engineering/architecture.md`
- `inception/reverse-engineering/component-inventory.md`
- `inception/reverse-engineering/technology-stack.md`

**3. Requirements Analysis: 요구사항 분석**

AI가 체계적으로 질문하며 요구사항을 수집합니다.

**AI의 분석:**

- 요청 명확성 (명확함/모호함/불완전함)
- 요청 타입 (신규 기능/버그 수정/리팩토링 등)
- 초기 범위 추정 (단일 파일/컴포넌트/시스템 전체)
- 초기 복잡도 추정 (간단함/보통/복잡함)

**4. User Stories: 사용자 스토리 (조건부)**

요구사항을 사용자 중심 스토리로 변환합니다.

**실행 조건:**

- 사용자가 직접 사용하는 기능
- 여러 사용자 유형이 있는 경우
- 복잡한 비즈니스 로직
- 팀 간 협업이 필요한 경우

**생성되는 스토리:**

`사용자 스토리 (INVEST 원칙):
- Independent (독립적)
- Negotiable (협상 가능)
- Valuable (가치 있음)
- Estimable (추정 가능)
- Small (작음)
- Testable (테스트 가능)

예시:
"플레이어로서 스페이스바를 눌러 캐릭터를 점프시킬 수 있다"

인수 기준:
- 스페이스바 입력 시 캐릭터가 위로 이동
- 점프 높이는 일정함
- 입력 지연 < 16ms`

**산출물**:

- `inception/user-stories/stories.md`
- `inception/user-stories/personas.md`

**5. Workflow Planning: 워크플로 계획**

AI가 전체 실행 계획을 수립합니다.

`실행 계획:

🔵 INCEPTION 단계:
✅ Workspace Detection (완료)
✅ Requirements Analysis (완료)
✅ User Stories (실행 예정)
⏭️ Application Design (스킵 - 단순한 구조)
✅ Units Generation (실행 예정)

🟢 CONSTRUCTION 단계:
✅ Functional Design (유닛별 실행)
✅ NFR Requirements (유닛별 실행)
⏭️ NFR Design (스킵 - 간단한 NFR)
⏭️ Infrastructure Design (스킵 - 클라이언트만)
✅ Code Generation (항상 실행)
✅ Build and Test (항상 실행)

예상 소요 시간: 약 3시간`

**산출물**: `inception/plans/execution-plan.md`

**6. Application Design: 애플리케이션 설계 (조건부)**

고수준 컴포넌트와 서비스 레이어를 설계합니다.

**수행 내용**:

- 시스템의 주요 컴포넌트 식별
- 각 컴포넌트의 책임과 역할 정의
- 컴포넌트 간 인터페이스 설계
- 서비스 레이어 구조 정의
- 의존성 관계 매핑

**산출물**:

- `inception/application-design/components.md` - 컴포넌트 정의
- `inception/application-design/component-methods.md` - 메서드 시그니처
- `inception/application-design/services.md` - 서비스 레이어
- `inception/application-design/component-dependency.md` - 의존성 매트릭스

**7. Units Generation: 유닛 생성 (조건부)**

시스템을 개발 유닛으로 분해합니다.

**개발 유닛이란?** 독립적으로 개발 가능한 작업 단위입니다.

- 마이크로서비스: 각 유닛이 독립 배포 가능한 서비스
- 모놀리스: 단일 유닛 내의 논리적 모듈

`Table Order 유닛 분해:

유닛 1: 주문 관리
- 담당 스토리: 주문 생성, 주문 조회
- 의존성: 없음
- 우선순위: 높음

유닛 2: 메뉴 관리
- 담당 스토리: 메뉴 조회, 메뉴 검색
- 의존성: 없음
- 우선순위: 높음

유닛 3: 결제 처리
- 담당 스토리: 결제 계산, 영수증 생성
- 의존성: 주문 관리
- 우선순위: 중간`

**산출물**:

- `inception/application-design/unit-of-work.md`
- `inception/application-design/unit-of-work-dependency.md`
- `inception/application-design/unit-of-work-story-map.md`

**이 단계의 가치**

프로젝트 정의 단계를 제대로 거치면:

**명확한 프로젝트 비전** 실행 가능한 유닛으로 분해된 잘 정의된 비즈니스 목적을 확보합니다.

**포괄적인 요구사항** 이해관계자 합의가 포함된 상세한 요구사항 문서를 얻습니다.

**우선순위가 지정된 백로그** 개발을 위해 매핑되고 우선순위가 지정된 사용자 스토리를 확보합니다.

**기술적 기반** 확립된 아키텍처 결정과 설계 패턴을 정의합니다.

**성공 메트릭** 정의된 성공 기준과 측정 프레임워크를 수립합니다.

**위험 평가** 기술적 위험을 미리 파악하고 완화 전략을 수립합니다.

---

**다음 단계로**

프로젝트 정의 단계가 끝나면 이런 것들이 준비됩니다:

- 검증된 요구사항 및 사용자 스토리
- 확립된 기술 아키텍처
- 명확한 성공 기준 및 승인 테스트
- 위험 평가 및 완화 전략
- 개발 로드맵 및 작업 계획

이제 구축 단계로 넘어가 실제 코드를 만들 준비가 완료되었습니다!
